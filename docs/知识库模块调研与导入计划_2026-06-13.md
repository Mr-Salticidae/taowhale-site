# 知识库模块调研与资料导入计划

> 调研日期：2026-06-13
> 背景：下一阶段工作是先将个人知识库（[Mr-Salticidae/knowledge-base](https://github.com/Mr-Salticidae/knowledge-base)）接入官网做测试，再将公司全部官方资料分类导入知识库板块。
> 核心痛点：公司资料量大但缺乏结构，学员被海量优质链接淹没，找不到想要的资料。

---

## 一、结论先行

**两步导入计划方向正确，但按当前代码，第一步测试就会撞墙——知识库模块目前没有搜索、没有批量导入、不支持 Markdown。** 这三个缺口在现有架构（FastAPI + SQLite）里都不难补，且用个人知识库（104 篇 markdown，含层级、标签、代码块）做测试集恰好能把所有边角全部暴露出来。

建议把工作排成三段而非两段：**先定分类法 → 接入个人库并顺手补齐 P0 能力 → 公司资料导入（链接型资料做成一等公民）**。

---

## 二、当前知识库模块现状审计

### 2.1 数据模型

核心表 `kb_docs`（`backend/main.py:77-94`），扁平结构：

| 字段 | 说明 |
|------|------|
| `level` | 三级访问控制：`all`(公开) / `group`(组专属) / `personal`(个人专属) |
| `group_id` / `owner_id` / `author_id` | 组、所有者、作者外键 |
| `title` / `summary` / `content` | 标题(≤120字) / 摘要(≤2000字) / 正文(≤50000字，纯文本) |
| `cat` | 分类，前后端写死 4 类：`prompt` / `workflow` / `review` / `tool` |
| `tags` | 逗号分隔自由文本，无独立表，不可聚合查询 |
| `link` | 外部链接，仅详情页底部一个按钮 |
| `icon` / `date` / `sort` / `created` / `updated` | 展示与排序辅助字段 |

### 2.2 API 现状（`backend/main.py:544-720`）

- `GET /api/kb/meta` — 权限元数据（staff 判断、组列表、人员列表）
- `GET /api/kb/docs?level=&group_id=&owner_id=&cat=` — 列表，仅 4 维过滤
- `GET /api/kb/docs/{id}` — 详情，带权限检查
- `POST / PUT / DELETE /api/kb/docs` — 逐篇增删改，staff 权限

### 2.3 权限分级（做得好的部分）

三层隔离清晰：游客/学员仅见 `level='all'`；工作人员（导师/官方/任一组成员，`main.py:290-296`）可见公开 + 自己的组库/个人库；官方账号全量可管。**这套权限体系无需大改。**

### 2.4 四个硬伤（面对海量资料）

1. **完全没有搜索** — 后端无搜索接口，前端无搜索框，学员只能靠 4 个分类过滤后逐条翻。这是"被淹没"的直接原因。
2. **没有批量导入** — 唯一入库方式是前端表单逐篇手填，无 CSV/JSON 导入接口，无第三方同步。
3. **不支持 Markdown** — 正文按纯文本换行渲染（`static/index.html:1681`），markdown 资料导入后格式全丢。
4. **分类写死且扁平** — 4 个分类硬编码在前后端；无父子层级（无法组织"图像生成 → Midjourney → 角色一致性"这类树）；tags 不能作为导航维度。

## 三、三段式工作计划

### 第 0 步（导入之前）：先和团队定分类法

"漫山遍野的优质链接"最危险的处理方式是原样倒进库里——那只是把混乱从网盘搬到网站。

- 用公司资料抽样，画出**两层分类树 + 标签维度**（建议维度：工具 / 学习阶段 / 难度 / 资料类型）
- 分类从代码硬编码改为**数据库表驱动**（新建 `kb_cats` 表，支持 `parent_id` 两层嵌套），后续调整分类不用改代码
- 原则：精选优于乱塞——垃圾文件会拖累检索质量，导入前先过一遍筛选

### 第 1 步（接入个人库测试）：顺手补齐三个 P0 能力

| 能力 | 实现方案 | 成本 |
|------|---------|------|
| 全文搜索 | SQLite 自带 FTS5 虚表（title/summary/content/tags），新增 `GET /api/kb/search?q=`；前端列表页加搜索框 | 低 |
| 批量导入 | `POST /api/kb/import`，吃 JSON 数组，官方权限，事务化提交；写一个本地脚本把 knowledge-base 的 markdown 批量转 JSON 推上去 | 低 |
| Markdown 渲染 | 前端引入 markdown 渲染库（如 marked + DOMPurify），详情页渲染 content | 低 |

个人知识库 104 篇文档是完美测试集：有层级目录、有标签、有代码块、有内链，能把搜索、导入、渲染的边角全部测到。

### 第 2 步（公司资料导入）：链接型资料做成一等公民

- 新增"链接卡片"资料类型：录入 URL 自动抓取标题/摘要（后端 fetch + 解析 meta 标签），列表页直接可点
- 导入时按规则批量分配 `level` / `cat` / `tags`，避免逐篇手选
- 长期：库结构化之后可接 Omni Learning 做个性化推荐——"找不到"的终极解法是**搜索、浏览、推荐**三条路并行，结构化数据是后两条的前提

### 优先级备忘（P1/P2）

- P1：标签拆独立表支持聚合导航；日期范围与排序方式；导入面板进管理后台
- P2：文档树形组织（`parent_id`）；FTS5 性能不够时迁移专用检索；权限批量规则
